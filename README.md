## การเข้าถึง (Accessibility)

ผ่าน **WCAG 2.2 ระดับ A และ AA** ทั้งสี่หน้า ตรวจด้วยสคริปต์วัดค่าจริงในเบราว์เซอร์
ที่ 1440 / 375 / 320 px — ไม่มีข้อความตกเกณฑ์คอนทราสต์ และไม่มีเป้ากดต่ำกว่า 24px

สิ่งที่ต้องระวังเวลาแก้สีในอนาคต:

- **อย่าใช้ `rgba()` กับสีข้อความ** ความโปร่งใสทำให้คอนทราสต์จริงต่ำกว่าค่าที่ประกาศไว้มาก
  (ของเดิมประกาศ `rgba(122,98,87,.45)` แล้ววัดได้ 1.85 ทั้งที่ดูเหมือนสีน้ำตาลเข้ม)
  ใช้สีทึบไปเลย และ `opacity` ระดับ element ก็มีปัญหาเดียวกัน
- **ปุ่มที่ใช้ gradient** ต้องผ่านเกณฑ์ที่ปลายอ่อนของ gradient ไม่ใช่ปลายเข้ม
- **แถวหัวใจบนต้นไม้คำอวยพร** เล็กกว่า 24px จึงต้องมีรายการคำอวยพรใต้ต้นไม้
  เป็นทางเข้าเดียวกันในขนาดที่กดได้ — ห้ามซ่อนรายการนั้น
- **สไลด์แกลเลอรีต้องมีปุ่มหยุด** (SC 2.2.2) ปุ่มอยู่มุมขวาบนของโมเสก

## ฟีเจอร์ที่ควรรู้

- **หน้าแรก**: ถ้าแขกไม่กด "Enter Our Story" ภายใน 5 วินาที การ์ดจะเปิดเอง
  พอวิดีโอจบจะค้างเฟรมสุดท้ายไว้ 2 วินาที แล้วค่อยจางเข้าหน้าแรก
  ปรับได้ที่ `INTRO_AUTOPLAY_MS` และ `INTRO_HOLD_MS` ใน `config.js`
- **อนิเมชันเล่นซ้ำได้**: ทุกส่วนที่มี scroll-reveal จะรีเซ็ตเมื่อเลื่อนพ้นจอ
  เลื่อนกลับขึ้นมาจึงได้ดูใหม่ทุกครั้ง
- **เลื่อนทีละฉาก**: ฉากเล่าเรื่องทั้งสี่ (หน้าแรก / บทกวีสองฉาก / Story) สูงหนึ่งจอเท่ากัน
  และ snap ให้หยุดตรงหัวฉาก เลื่อนหนึ่งครั้งจึงได้ดูหนึ่งฉากเต็ม ๆ
  ปรับได้ที่บล็อก SCROLL RHYTHM ใน `home.css`
- **การเริ่ม/รีเซ็ตอนิเมชัน**: `main.js` ใช้ IntersectionObserver สองตัวที่เกณฑ์ไม่เท่ากัน
  เกณฑ์ "เริ่ม" คือโผล่บนจอ (เว้นขอบล่าง 12%) เกณฑ์ "รีเซ็ต" คือออกนอกจอหมดแล้ว
  ฉากจึงเริ่มตรงจังหวะ เล่นจนจบโดยไม่โดนขัด และเลื่อนกลับมาได้ดูใหม่ทุกครั้ง
- **โมโนแกรมอาหรับเขียนสด**: หน้าแรกวาดตัวอักษรบนการ์ดตามลำดับการเขียนจริง
  (โครงตัวอักษรก่อน แล้วค่อยเติมจุด) ใช้ `welcome-nomono.png` เป็นการ์ดเปล่า
  แล้วเปิดโมโนแกรมตามรอยปากกาด้วย mask — ดูบล็อก HERO ใน `home.css`
- **ฉาก "เป็นคู่ ๆ"**: นักเดินป่าสองคนเดินเข้าหากันแล้วโอบกอด เป็น SVG ล้วน
  ใช้ภาษาเส้นชุดเดียวกับอวตารในหน้าคำอวยพร
- **พิมพ์ดีด**: ข้อความอังกฤษในฉาก blessing แรกพิมพ์ทีละตัว แล้วคำแปลไทยจึงขึ้น
  ปรับความเร็วที่ `TYPE_SPEED` ใน `home.js`
- **ฉาก Story**: มีลำดับการเล่าเรื่องเมื่อเลื่อนถึง — ภูเขาสว่างขึ้น → ป้ายบอกสถานที่
  → ประโยคเปิดเรื่อง → เขาเข้ามาจากซ้าย เธอเข้ามาจากขวา → แสงตะเกียงบรรจบกัน
  (คุมด้วย `.story-scene.in-view` ใน `home.css`)

- **เพลงพื้นหลัง**: ค่าเริ่มต้นคือ "เปิด" วนซ้ำอัตโนมัติเมื่อจบเพลง
  มีปุ่มเปิด/ปิดเสียงมุมบนขวาของหน้าแรก จำค่าที่เลือกไว้ข้ามหน้า
  เปลี่ยนเพลงได้ที่ `VIDEO_ID` / `START_SECONDS` ใน `assets/js/config.js`

  ข้อจำกัดที่แก้ไม่ได้: เบราว์เซอร์ทุกตัวห้ามเล่นเสียงเองก่อนที่ผู้ใช้จะแตะหน้าจอ
  เว็บจึงเริ่มเพลงตอนกด "Enter Our Story" และถ้าเข้าหน้าแรกโดยข้าม intro
  (เช่นกดกลับมาจากหน้าอื่น) จะเริ่มเพลงทันทีที่แขกแตะที่ใดก็ได้บนหน้า
  ปุ่มเสียงจะแสดงสถานะจริงเสมอ ถ้ายังไม่มีเสียงจะขึ้นเป็นปิด กดครั้งเดียวก็ติด

- **Countdown**: ตัวเลขพลิกแบบป้ายบอกเวลาสนามบิน เมื่อถึงวันงานจะเป็น 00:00:00:00
  เปลี่ยนหัวข้อเป็น "Today Is The Day" แล้วจุดพลุอัตโนมัติ
- **ต้นไม้คำอวยพร** (wishes.html): คำอวยพร 1 ข้อ = หัวใจ 1 ดวงบนกิ่ง ยิ่งมีคนอวยพร
  ต้นไม้ยิ่งเต็ม แตะหัวใจเพื่ออ่านคำอวยพรของคนนั้น
- **โหมดเต็มจอ** (ปุ่มไอคอนมุมบนขวาของต้นไม้ — ใช้ฉายบนจอทีวีในวันงาน)
  รองรับทั้ง Fullscreen API และโหมดจำลองสำหรับ iOS Safari ที่ไม่รองรับ API นี้
  จอแนวตั้งจะสลับให้แถบลำดับไปอยู่ด้านล่างแทน

  ผังจอ:
  - ซ้าย: ต้นไม้ + การ์ดคำอวยพร (รูปผู้เขียน + ข้อความ) และหัวใจดวงที่ตรงกัน
    จะขยายพร้อมเปิดข้อความค้างไว้บนกิ่ง
  - ขวา: ลำดับคำอวยพรทั้งหมด เรียงใหม่→เก่า กดที่รายการเพื่อฉายข้อความนั้นได้

  จังหวะการหมุน — แบ่งเป็น 2 เลน:
  - **เลนหลัก** วนคำอวยพรทั้งหมดตามลำดับ ข้อความละ 5 วินาที
  - **เลนแทรก** คำอวยพรที่เพิ่งส่งเข้ามาจะแทรกขึ้นทันที ค้าง 7 วินาที
    พร้อมป้าย "เพิ่งส่งเข้ามา" แล้วคืนเลนหลัก**ที่ตำแหน่งเดิม** (ไม่รีเซ็ตรอบ)
  - ถ้าหลายคนส่งพร้อมกัน จะเข้าคิวแทรกทีละคน แต่ติดกันได้ไม่เกิน 3 ครั้ง
    แล้วต้องคั่นด้วยคำอวยพรเก่า 1 อัน กันจอกลายเป็นฟีดคนใหม่อย่างเดียว
  - ระหว่างฉายเต็มจอจะดึงข้อมูลใหม่ทุก 10 วินาที (แขกส่ง → ขึ้นจอใน ~10 วินาที)
  - หัวใจจะ "ผลิ" เฉพาะดวงที่เพิ่งเข้ามา ดวงเดิมอยู่นิ่ง ไม่เด้งซ้ำทุกรอบ

  ค่าที่ปรับได้ใน `assets/js/wishes.js`: `NEW_HOLD_MS` (เวลาค้างของใหม่),
  `NEW_STREAK_MAX` (แทรกติดกันได้กี่ครั้ง), `FULLSCREEN_POLL_MS` (ความถี่ดึงข้อมูล)
  ส่วนความเร็วเลนหลักอยู่ที่ `WISHES_INTERVAL` ใน `config.js`

## แก้ค่าที่ใช้บ่อย

ทุกอย่างอยู่ใน `assets/js/config.js`:
- `VIDEO_ID` / `START_SECONDS` — เพลงพื้นหลัง (YouTube)

## Deploy Apps Script (ระบบ RSVP)

หน้า RSVP ส่งข้อมูลไป endpoint เดียวกับระบบคำอวยพร โดยแนบ `type: "rsvp"`
ต้องเพิ่ม handler ฝั่ง Apps Script ก่อนระบบจึงจะทำงาน:

1. เปิด script.google.com → โปรเจกต์เดิมที่ผูกกับ Google Sheet คำอวยพร
2. เพิ่มโค้ดจาก `apps-script/Code.gs` ในส่วน RSVP:
   - ฟังก์ชัน `handleRsvp_` และ `RSVP_SHEET_NAME` ทั้งก้อน
   - ใน `doPost` เดิม เพิ่มเช็ค `if (data.type === "rsvp") return handleRsvp_(data);` ไว้บนสุดก่อน logic เดิม
3. Deploy → Manage deployments → แก้ deployment เดิม → New version → Deploy
   (ห้ามสร้าง deployment ใหม่ — URL จะเปลี่ยนแล้วเว็บจะพัง)
4. ชีทชื่อ `RSVP` จะถูกสร้างอัตโนมัติเมื่อมีคนตอบรับครั้งแรก
   คอลัมน์: Timestamp | Fullname | Attending | Guests | Side
